# Contributing to FlowDesk Public Documentation

Thank you for your interest in improving the FlowDesk public repository.

## Contribution Scope

This repository is focused on:

- Product documentation
- Public architecture explanations
- Showcase assets and narrative clarity
- Public issue templates and collaboration workflows

The FlowDesk production application is proprietary and maintained in a separate private repository. Code contributions to private production systems are not accepted through this repository.

## How to Contribute

You can contribute by:

- Correcting typos, clarity issues, or outdated statements
- Improving documentation structure and readability
- Suggesting improvements to roadmap communication
- Proposing public-facing feature documentation enhancements

## Opening Issues

When opening an issue:

- Be specific and concise.
- Include references to affected files/sections.
- Keep discussion focused on public documentation and showcase content.
- Do not include secrets, credentials, internal endpoints, or customer data.

For security concerns, follow [SECURITY.md](SECURITY.md).

## Pull Request Expectations

Please ensure pull requests:

- Have a clear summary of what changed and why
- Stay within the public documentation scope
- Avoid unsupported claims about implementation completeness
- Include only sanitized, non-sensitive information
- Keep edits focused and easy to review

## Style and Content Guidelines

- Use professional, factual language.
- Distinguish planned capabilities from verified implementation.
- Avoid marketing exaggeration and unverified performance claims.
- Keep terminology consistent across files.

We appreciate thoughtful contributions that improve clarity and trust in FlowDesk's public project narrative.
